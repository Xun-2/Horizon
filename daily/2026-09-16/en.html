Measuring and Improving Agent Consistency

Background

The authors argue that average task accuracy conceals a production reliability problem: an agent may succeed once and fail when asked to perform the same task again. On AppWorld, a GPT-4.1 ReAct agent achieved a Mean@5 success rate of 77.4%, but passed all five runs for only 53.0% of tasks, producing a 24.4-percentage-point consistency gap.

Solution

To measure this difference, the post distinguishes Mean@k, the average success rate across repeated runs, from Pass^k, the share of tasks that succeed on every run; Pass^k is the stricter counterpart to Pass@k, which counts tasks succeeding at least once. The authors attribute inconsistency to near-tied token probabilities at individual decisions, which can be reordered by platform-level numerical and batching effects even with temperature-zero decoding and fixed seeds, with small changes compounding across long trajectories. Their black-box Consistency Analyzer takes one recorded trajectory and resamples each decision point with five completions, identifying steps likely to flip without requiring logits, ground truth, tool calls, or an end-to-end replay. ALTK-Evolve then turns those flagged steps into reusable consistency guidelines, such as verifying note matches or using line-anchored counting logic. On 168 AppWorld test_normal tasks, the approach raised Pass^5 from 53.0% to 69.0% and Mean@5 from 77.4% to 81.0%, cutting the gap to 12.0 points; gains also transferred to related tasks and a weaker model, though the evidence remains limited to the reported experiments.

Takeaway

The authors' central claim is that reliability under repetition is a distinct evaluation axis from capability, so average accuracy alone can make an agent look more dependable than it is. Diagnosing and stabilizing uncertain decisions may improve repeatability without sacrificing average performance, but broader benchmarks and reproducible methodology are still needed to establish how generally this works.

Strix Agent Found Baseten Production GitHub Token in 25 Minutes

Strix reported that its penetration-testing agent obtained administrative access to Baseten's production GitHub repositories within 25 minutes. The agent found an active personal access token for the basetenbot account in Docker build history after locating a Baseten image repository.

Details and sources

Strix reported that its penetration-testing agent obtained administrative access to Baseten's production GitHub repositories within 25 minutes. The agent found an active personal access token for the basetenbot account in Docker build history after locating a Baseten image repository. According to the disclosure, the token allowed admin and push access to Baseten's main product repository, its cluster-driving GitOps repository, and its Homebrew tap, plus read/write access to other private repositories, including customer-specific repositories. Baseten subsequently made the exposed Harbor project private and rotated the token after Strix reported that it remained active.

Summary

Strix reported that its penetration-testing agent obtained administrative access to Baseten's production GitHub repositories within 25 minutes. The agent found an active personal access token for the basetenbot account in Docker build history after locating a Baseten image repository. According to the disclosure, the token allowed admin and push access to Baseten's main product repository, its cluster-driving GitOps repository, and its Homebrew tap, plus read/write access to other private repositories, including customer-specific repositories. Baseten subsequently made the exposed Harbor project private and rotated the token after Strix reported that it remained active.

Background

Docker images are built from layered filesystem changes and configuration metadata, so credentials accidentally included during a build can remain recoverable from image history even after files are removed. A GitHub personal access token (PAT) is a bearer credential whose effective access depends on its scopes and repository permissions; if exposed and still active, it can authenticate automated or human actions as the associated account.

Impact

The exposed token could have enabled source-code modification, GitOps-driven infrastructure changes, and unauthorized access to private customer-related repositories.

Community Discussion

Commenters largely viewed the incident as evidence that security agents can automate discoveries that humans could make but might not pursue as quickly or systematically. Discussion also questioned whether Strix offered capabilities beyond general-purpose agents and raised concerns about the legality of probing systems without explicit authorization.
