衡量并提升智能体重复执行的一致性

一次成功并不代表智能体能够可靠地重复完成同一任务，尤其是在对账、合同检查等关键工作中。 作者指出，常见的平均准确率 Mean@k 只能回答智能体平均表现如何，却掩盖了重复运行时的波动：AppWorld 上由 GPT-4.1 驱动的 ReAct 智能体五次运行平均成功率为 77.4%，但五次都成功的任务仅占 53.0%，两者相差 24.4 个百分点。

背景

一次成功并不代表智能体能够可靠地重复完成同一任务，尤其是在对账、合同检查等关键工作中。作者指出，常见的平均准确率 Mean@k 只能回答智能体平均表现如何，却掩盖了重复运行时的波动：AppWorld 上由 GPT-4.1 驱动的 ReAct 智能体五次运行平均成功率为 77.4%，但五次都成功的任务仅占 53.0%，两者相差 24.4 个百分点。

方案

文章用 Pass^k 衡量所有 k 次运行都成功的任务比例，并将 Mean@k 与 Pass^k 的差定义为一致性差距；它不同于允许多次尝试后取一次成功的 Pass@k，且满足 Pass^k ≤ Mean@k ≤ Pass@k。作者认为，不稳定性来自智能体轨迹中概率分布平坦、多个决策几乎势均力敌的步骤，平台浮点运算、批处理等微小扰动就可能改变 API 选择、参数或重试决定，而温度为 0 和固定随机种子也不能消除这种近似决策带来的变化。为定位这些步骤，Consistency Analyzer 只需一条已有轨迹，不依赖真实标签或模型内部信息，在离线重放每个决策上下文时一次请求 5 个补全，生成逐步一致性评分，无需重新执行工具调用或完整任务。随后，ALTK-Evolve 将高风险步骤转化为可复用指南，例如要求用行锚定正则表达式统计笔记中的复选标记，并核验搜索结果是否对应正确笔记。对 AppWorld test_normal 的 168 个任务进行五次新运行后，指南使 Pass^5 从 53.0% 提升到 69.0%，Mean@5 从 77.4% 提升到 81.0%，将差距缩小到 12.0 个百分点；相近任务的 Pass^5 仍提升 13.0 个百分点，较弱的 gpt-oss-120b 在同任务上提升 6.0 个百分点，但证据主要来自有限模型和单一基准。

启示

作者的核心结论是，智能体能力与重复执行可靠性是两个需要分别测量和优化的维度，单独报告平均准确率会把“偶尔成功”误认为“值得依赖”。通过轨迹重采样识别易翻转的决策，再生成针对性指南，有望在不牺牲平均准确率的情况下提升一致性，但其跨模型、跨任务和生产环境的普适性仍需更多验证。

Strix智能体25分钟获取Baseten生产GitHub管理权限

Strix披露称，其渗透测试智能体在25分钟内从Baseten公开镜像的Docker构建历史中发现了仍然有效的basetenbot GitHub个人访问令牌。 该令牌对Baseten主产品仓库、用于驱动集群的GitOps仓库和Homebrew tap拥有管理或推送权限，并可读写其他私有仓库，其中包括面向特定客户的仓库。

详情与原文

Strix披露称，其渗透测试智能体在25分钟内从Baseten公开镜像的Docker构建历史中发现了仍然有效的basetenbot GitHub个人访问令牌。该令牌对Baseten主产品仓库、用于驱动集群的GitOps仓库和Homebrew tap拥有管理或推送权限，并可读写其他私有仓库，其中包括面向特定客户的仓库。事件表明，构建历史中的凭据泄露可迅速升级为生产基础设施、软件供应链及客户相关代码的访问风险。根据披露者在社区提供的时间线，问题于7月13日晚报告，Baseten次日先将Harbor项目设为私有，随后确认问题为严重级别并轮换令牌。

事件概述

Strix披露称，其渗透测试智能体在25分钟内从Baseten公开镜像的Docker构建历史中发现了仍然有效的basetenbot GitHub个人访问令牌。该令牌对Baseten主产品仓库、用于驱动集群的GitOps仓库和Homebrew tap拥有管理或推送权限，并可读写其他私有仓库，其中包括面向特定客户的仓库。事件表明，构建历史中的凭据泄露可迅速升级为生产基础设施、软件供应链及客户相关代码的访问风险。根据披露者在社区提供的时间线，问题于7月13日晚报告，Baseten次日先将Harbor项目设为私有，随后确认问题为严重级别并轮换令牌。

背景

Docker 镜像由多个层组成，构建过程中的文件和元数据可能会保留在镜像历史中，即使相关凭据后来从当前文件中删除，仍可能被提取。GitHub 个人访问令牌（PAT）可代表账户访问代码仓库，其实际权限取决于令牌配置；本案中，令牌出现在镜像配置的 `history[].created_by` 字段中。

实际影响

受影响令牌的广泛权限使Baseten的生产代码、GitOps配置、发布渠道及部分客户相关仓库面临被读取或篡改的风险。

社区讨论

评论者普遍认为，这一案例体现了智能体的主要优势是以较低成本快速执行人类能够完成但往往缺乏动力进行的深入排查，而不一定是发现人类无法发现的漏洞。讨论同时肯定了Baseten的响应，也质疑Strix相较Claude或Codex等通用智能体的独特性，并提出未经明确授权开展此类测试可能涉及法律问题。
