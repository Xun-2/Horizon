From Read-Only Copilot to SQL Server Sysadmin

In the author's research on Microsoft's Copilot integration in SQL Server Management Studio, the central concern was that Copilot executes through the currently connected database session, potentially inheriting highly privileged rights. SQL Copilot was instructed to operate in read-only mode, but the post argues that a model instruction is not a security boundary, especially when enforcement depends on recognizing dangerous SQL patterns.

Background

In the author's research on Microsoft's Copilot integration in SQL Server Management Studio, the central concern was that Copilot executes through the currently connected database session, potentially inheriting highly privileged rights. SQL Copilot was instructed to operate in read-only mode, but the post argues that a model instruction is not a security boundary, especially when enforcement depends on recognizing dangerous SQL patterns.

Solution

Reverse engineering showed that the ReadFromDatabase tool used a regex-based LocalSqlExecutionAccessChecker, without a separate low-privilege connection or database-enforced read-only permissions. The author bypassed the blocklist by assigning a procedure name to a variable and executing it indirectly, then used sp_executesql to run arbitrary statements such as DROP, INSERT, UPDATE, and DELETE; related paths through xp_dirtree and RestoreVerifyBackupFile also enabled data exfiltration or arbitrary SQL execution. The attack surface extended beyond direct prompts because Copilot incorporated database content, files, schema information, metadata, and, according to the post, persistent AGENTS.md and CONSTITUTION.md instructions stored as extended properties. A user with comparatively limited permissions could plant those instructions, which a later, more privileged Copilot user would follow; the author's demonstrated chain used this indirect prompt injection to bypass read-only controls and add the attacker to SQL Server's sysadmin role. The post recommends permission-enforced read-only execution, avoiding highly privileged connections, and treating persistent database instructions as part of the permission and trust model.

Takeaway

The author's broader conclusion is that tool-using AI agents must enforce dangerous capabilities through independent technical permissions, not prompts or fragile classifiers. Once an agent can execute arbitrary SQL, indirect prompt injection and database-stored instructions can turn ordinary content and metadata into privilege-escalation mechanisms.

Transformers v5.18.0 adds diarization and multimodal model support

Hugging Face Transformers v5.18.0 adds support for several models, including NVIDIA’s open-weight Nemotron 3 Diarization, NemotronH Omni, NAVER’s HyperCLOVAX Vision V2, and GTE. Nemotron 3 Diarization supports streaming and offline “who spoke when” inference for up to eight speakers, orders speakers by their first appearance, and uses one checkpoint with configurable latency from an 80 ms input buffer to a 30.4-second offline-style buffer; its output resolution can be configured in 10 ms increments, and chunked inference removes the maximum audio-duration limit.

Details and sources

Hugging Face Transformers v5.18.0 adds support for several models, including NVIDIA’s open-weight Nemotron 3 Diarization, NemotronH Omni, NAVER’s HyperCLOVAX Vision V2, and GTE. Nemotron 3 Diarization supports streaming and offline “who spoke when” inference for up to eight speakers, orders speakers by their first appearance, and uses one checkpoint with configurable latency from an 80 ms input buffer to a 30.4-second offline-style buffer; its output resolution can be configured in 10 ms increments, and chunked inference removes the maximum audio-duration limit. The release also adds multimodal text, image, video, and optional audio reasoning for NemotronH Omni, text/image/video support and thinking tokens for HyperCLOVAX Vision V2, and GTE encoder support for several multilingual and long-context retrieval checkpoints. It includes breaking changes affecting ROCm attention routing, DETR image processing, indexer layer types, vLLM video-token counting, legacy model standards, and the Kernels version, alongside numerous compatibility, testing, distributed-inference, audio, vision, and hardware-backend fixes.

Background

Transformers is Hugging Face’s model and inference library, and model additions make new architectures and checkpoints available through its common APIs. Speaker diarization identifies which speaker is active at each point in an audio recording; streaming diarization performs that task incrementally while trading latency and context for responsiveness.

Impact

Developers can integrate Nemotron 3 Diarization into real-time or offline speech systems with tunable latency, speaker capacity, and frame resolution, while users of affected backends and integrations may need to review the listed breaking changes before upgrading.

Magnitude Launches a Self-Tuning Inference Engine for Agents

Magnitude is an open-source, Apache 2.0 inference engine built in Rust for running local AI agents on Mac, Linux, and Windows, with kernels tuned on the user’s hardware. Its developers report up to 2x faster performance than llama.cpp and lower per-agent memory use, citing tests with Qwen 3.6 35B A3B at 4-bit quantization and a 64K context: on an M4 Pro, decode was 30 to 57 tokens per second and memory use was 28% lower; on a DGX Spark, decode was 49 to 58 tokens per second and memory use was 27% lower.

Details and sources

Magnitude is an open-source, Apache 2.0 inference engine built in Rust for running local AI agents on Mac, Linux, and Windows, with kernels tuned on the user’s hardware. Its developers report up to 2x faster performance than llama.cpp and lower per-agent memory use, citing tests with Qwen 3.6 35B A3B at 4-bit quantization and a 64K context: on an M4 Pro, decode was 30 to 57 tokens per second and memory use was 28% lower; on a DGX Spark, decode was 49 to 58 tokens per second and memory use was 27% lower. The engine also uses dynamic memory allocation and hybrid paged attention to support concurrent agent sessions, and its desktop app can start and stop models on demand for tools including Pi, OpenCode, Hermes, and Codex. Background

Model distillation is a technique for transferring capabilities from a protected, typically larger model to another model by using its outputs as training data. In this context, adversarial distillation refers to attempts to extract protected model reasoning through coordinated use rather than authorized model development.

Impact

The disruption limits this campaign’s unauthorized extraction of protected model reasoning, while OpenAI’s planned defense improvements are likely to make similar adversarial distillation attempts harder to conduct.
