SQL Copilot：从只读查询到系统管理员

作者在 BlueHat Asia 2026 分享了对 SQL Server Management Studio（SSMS）中 SQL Copilot 的研究，并将其与微软公布的关键权限提升漏洞 CVE-2026-65669 联系起来。 Copilot 使用查询窗口当前连接的数据库权限执行操作，因此当连接账户权限很高时，代理控制失效可能影响整个 SQL Server；问题在于，所谓“只读”最初主要依赖系统提示，而不是数据库权限或隔离连接。

详情与原文

作者在 BlueHat Asia 2026 分享了对 SQL Server Management Studio（SSMS）中 SQL Copilot 的研究，并将其与微软公布的关键权限提升漏洞 CVE-2026-65669 联系起来。Copilot 使用查询窗口当前连接的数据库权限执行操作，因此当连接账户权限很高时，代理控制失效可能影响整个 SQL Server；问题在于，所谓“只读”最初主要依赖系统提示，而不是数据库权限或隔离连接。

背景

作者在 BlueHat Asia 2026 分享了对 SQL Server Management Studio（SSMS）中 SQL Copilot 的研究，并将其与微软公布的关键权限提升漏洞 CVE-2026-65669 联系起来。Copilot 使用查询窗口当前连接的数据库权限执行操作，因此当连接账户权限很高时，代理控制失效可能影响整个 SQL Server；问题在于，所谓“只读”最初主要依赖系统提示，而不是数据库权限或隔离连接。

方案

作者通过查看 Copilot 的工具和本地聊天日志，并使用 ILSpy 逆向代码发现，ReadFromDatabase 的只读检查由 LocalSqlExecutionAccessChecker 中的正则表达式分类器完成，且没有额外的低权限连接或真正的只读权限约束。通过把存储过程名放入变量再执行，攻击者可以绕过针对 EXEC 的拦截，并进一步调用 sp_executesql 执行 DROP、INSERT、UPDATE、DELETE 等任意 T-SQL；xp_dirtree 还可把查询结果逐行放入 SMB 路径，RestoreVerifyBackupFile 工具则提供了另一条传入任意 SQL 的路径。攻击不必来自用户的直接提示：Copilot 会读取数据库内容、SQL 文件、元数据以及支持的数据库指令，恶意注释可以诱导它执行写操作。更严重的是，低权限用户能够通过 extended properties 写入作用于对象的 AGENTS.md，或影响全库的 CONSTITUTION.md；当高权限用户之后使用 Copilot 时，这些持久化指令会进入上下文，形成“低权限写入、高权限执行”的链条，作者演示了从 db_owner 控制指令、绕过只读限制，到把攻击者加入 sysadmin 的过程。

启示

作者的核心结论是，AI 代理的只读能力必须由数据库权限等不可绕过的安全不变量保证，不能依赖模型指令或脆弱的正则过滤；同时，代理不应使用不必要的高权限连接。数据库中的持久化 AI 指令也改变了原有权限模型，使间接提示注入在代理能够执行任意 SQL 时成为现实的权限提升风险。

Transformers v5.18.0 新增 Nemotron 3 Diarization 等模型支持

Hugging Face Transformers 发布 v5.18.0，新增了 Nemotron 3 Diarization、NemotronH Omni、HyperCLOVAX Vision V2 和 GTE 等模型支持。 Nemotron 3 Diarization 是 NVIDIA 的开放权重流式说话人分离模型，支持流式与离线推理，最多处理八位说话人，并按照说话人首次出现在输入音频中的顺序输出结果。

详情与原文

Hugging Face Transformers 发布 v5.18.0，新增了 Nemotron 3 Diarization、NemotronH Omni、HyperCLOVAX Vision V2 和 GTE 等模型支持。Nemotron 3 Diarization 是 NVIDIA 的开放权重流式说话人分离模型，支持流式与离线推理，最多处理八位说话人，并按照说话人首次出现在输入音频中的顺序输出结果。该模型基于 Arrival-Order Speaker Cache 和用于 Streaming Sortformer 的 FIFO 队列，使用同一个检查点支持从 80 毫秒输入缓冲区到 30.4 秒离线式缓冲区的可配置延迟配置，并支持以 10 毫秒为倍数的输出帧分辨率；通过分块推理时，音频时长不受限制。版本同时包含多项破坏性变更，以及围绕 ROCm、图像处理、视频输入、专家并行和硬件加速等功能的修复与改进。

相关背景

说话人分离旨在确定音频中“谁在什么时候说话”，是会议转写、语音分析和多说话人交互系统的基础能力。流式推理会在音频持续输入时逐步生成结果，而离线推理通常等待更长音频或完整输入后处理；可配置缓冲区可以在响应延迟与上下文范围之间进行调整。

实际影响

语音系统开发者可以直接在 Transformers 中使用同一 Nemotron 3 Diarization 检查点构建支持不同延迟、帧分辨率和长音频场景的流式或离线说话人分离流程。

Magnitude推出可自优化的本地智能体推理引擎

YC S25 项目 Magnitude 发布了一款面向本地智能体的跨平台开源推理引擎，支持 Mac、Linux 和 Windows，并声称能够在实际运行硬件上自动编译、调优 GPU 内核。 该引擎使用 Rust 构建，包含自定义 GPU 内核运行时和自动调优器，还提供动态内存分配与混合分页注意力，以支持长会话、多并发智能体并减少单个智能体的内存占用。

详情与原文

YC S25 项目 Magnitude 发布了一款面向本地智能体的跨平台开源推理引擎，支持 Mac、Linux 和 Windows，并声称能够在实际运行硬件上自动编译、调优 GPU 内核。该引擎使用 Rust 构建，包含自定义 GPU 内核运行时和自动调优器，还提供动态内存分配与混合分页注意力，以支持长会话、多并发智能体并减少单个智能体的内存占用。项目方以 4-bit Qwen 3.6 35B A3B、64K 上下文且不使用推测解码的测试称，在 M4 Pro 48 GB 的 Metal 环境中，相比 llama.cpp 解码速度从每秒 30 个 token 提升至 57 个、预填充速度提升 9%，单智能体内存使用量减少 28%；在 DGX Spark 的 CUDA 环境中，解码速度从每秒 49 个 token 提升至 58 个、预填充速度提升 23%，内存使用量减少 27%。Magnitude 以 Apache 2.0 许可证发布，并通过桌面应用接入 Pi、OpenCode、Hermes 和 Codex 等智能体，但目前性能优势主要来自项目方提供的基准，测试方法和更广泛的可复现结果仍有限。
