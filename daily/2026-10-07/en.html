Transformers v5.19.0 Adds EmbeddingGemma2 and Expands MoE Support

Hugging Face Transformers v5.19.0 adds support for Google's EmbeddingGemma 2, a multimodal embedding model built on the Gemma 4 architecture that maps text, images, audio, and video into a shared 768-dimensional vector space. The model supports cross-modal retrieval, semantic similarity, clustering, and classification, with Matryoshka embeddings that can be truncated to 512, 256, or 128 dimensions, configurable visual and video token budgets, and optional disabling of unused vision or audio towers to reduce memory use.

Details and sources

Hugging Face Transformers v5.19.0 adds support for Google's EmbeddingGemma 2, a multimodal embedding model built on the Gemma 4 architecture that maps text, images, audio, and video into a shared 768-dimensional vector space. The model supports cross-modal retrieval, semantic similarity, clustering, and classification, with Matryoshka embeddings that can be truncated to 512, 256, or 128 dimensions, configurable visual and video token budgets, and optional disabling of unused vision or audio towers to reduce memory use. The release also introduces token dispatch for expert parallelism, makes it the default for Qwen3 MoE and Mellum, and updates Trainer support for expert parallelism. Several compatibility-sensitive changes affect MoE router-logit outputs, OWLv2 image-query selection, continuous-batching attention configuration, cache updates, and quantized-cache behavior.

Background

Embedding models convert inputs into vectors so systems can compare semantic similarity, retrieve related content, or group examples. Multimodal embedding models extend this approach across different media types by placing them in a shared vector space, while Matryoshka Representation Learning allows a full embedding to be shortened for lower storage or retrieval costs.

Impact

AI developers can use Transformers v5.19.0 to build cross-modal retrieval and classification pipelines with EmbeddingGemma 2, but users upgrading existing MoE, OWLv2, attention, or cache integrations may need to adjust code for the documented behavior changes.

Impact

Developers building classification, routing, tagging, or other binary-decision features can evaluate a dedicated API path, but they should benchmark quality, latency, and total cost against their existing models because the available evidence is preliminary.
