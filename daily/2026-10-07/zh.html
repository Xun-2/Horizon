Transformers 5.19.0 支持 EmbeddingGemma2

Hugging Face Transformers 发布 v5.19.0，新增对 Google EmbeddingGemma2 的支持。 该多模态嵌入模型基于 Gemma 4 架构，可将文本、图像、音频和视频单独或组合编码到共享的 768 维向量空间，用于跨模态检索、语义相似度、聚类和分类。

详情与原文

Hugging Face Transformers 发布 v5.19.0，新增对 Google EmbeddingGemma2 的支持。该多模态嵌入模型基于 Gemma 4 架构，可将文本、图像、音频和视频单独或组合编码到共享的 768 维向量空间，用于跨模态检索、语义相似度、聚类和分类。模型支持 Matryoshka 表征学习，可将向量截断为 512、256 或 128 维，并可配置视觉与视频 token 预算，加载时禁用未使用的视觉或音频塔以节省内存。此版本还调整了 MoE 模型的路由器 logits 返回方式，改进专家并行和分层缓存配置，并修复量化缓存处理等问题；使用相关连续批处理、MoE 或自定义缓存代码的用户需要关注兼容性变化。

发布摘要

Hugging Face Transformers 发布 v5.19.0，新增对 Google EmbeddingGemma2 的支持。该多模态嵌入模型基于 Gemma 4 架构，可将文本、图像、音频和视频单独或组合编码到共享的 768 维向量空间，用于跨模态检索、语义相似度、聚类和分类。模型支持 Matryoshka 表征学习，可将向量截断为 512、256 或 128 维，并可配置视觉与视频 token 预算，加载时禁用未使用的视觉或音频塔以节省内存。此版本还调整了 MoE 模型的路由器 logits 返回方式，改进专家并行和分层缓存配置，并修复量化缓存处理等问题；使用相关连续批处理、MoE 或自定义缓存代码的用户需要关注兼容性变化。

背景

多模态嵌入模型会把不同类型的数据映射到同一个向量空间，使文本能够检索图像、音频或视频等跨模态内容。Matryoshka 表征学习允许从完整向量中截取较短前缀，在降低存储和检索成本的同时保留部分语义表示能力。

影响

AI 工程师可以直接通过 Transformers 集成 EmbeddingGemma2，构建支持文本、图像、音频和视频的统一向量检索与相似度系统；升级包含 MoE、连续批处理或自定义缓存逻辑的项目时则需要检查输出结构和缓存接口变化。

核心摘要

OpenAI 已开放 Decisions API 公共测试版，面向需要快速生成“是/否”结果或置信度判断的场景。该接口被定位为专门的决策型模型服务，可能让应用在模型选择、推理延迟和调用成本之间采用不同于通用生成 API 的架构。现有材料未提供具体模型规格、定价、性能数据或兼容性限制，因此其实际优势仍需根据官方文档和测试结果评估。

相关概念

分类任务是根据输入内容判断其类别或标签；二元分类通常输出“是/否”，置信度则表示模型对判断结果的确信程度。传统做法可以通过提示通用模型完成这类任务，而专用决策接口则将这类判断作为独立任务提供。

实际影响

需要大量分类、路由或界面选择判断的开发者可以评估专用决策接口，以降低延迟或避免为简单判断调用完整生成模型，但目前缺乏足够数据证明其成本和质量优势。

社区讨论

评论者普遍将该 API 与 Jev、Mercury Decide 及本地开源分类模型比较，关注快速输出二元结果或置信度是否足以替代部分提示式分类任务；有初步测试声称其速度约为 Responses API 的 10 倍，但评论也明确提到评测规模有限，且质量和成本结论仍不确定。另有观点认为，专用决策模型和开源模型的扩散可能加剧推理价格竞争，并推动 AI 服务进一步商品化。
