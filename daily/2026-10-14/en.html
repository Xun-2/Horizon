Background

Embrace The Red describes a Microsoft Copilot vulnerability affecting Visual Studio and SQL Server Management Studio (SSMS), which share the vulnerable Microsoft.VisualStudio.Copilot.Core.dll. Copilot was intended to prevent agents from modifying sensitive settings and MCP configuration files, but Windows treats a filename’s trailing ASCII period as insignificant when it is processed through ordinary Win32 file APIs.

Solution

The protection compared the requested filename as a string, so a name such as .mcp.json. or settings.VisualStudio.json. passed validation even though Windows later normalized it to the protected file. The author also found path-traversal variants, including paths appearing to start within a trusted Extensions directory but resolving elsewhere, and showed how readable installation metadata could help locate user settings reliably. A compromised or indirectly prompt-injected Copilot could therefore alter MCP configuration, enable a malicious server, or—specifically in Visual Studio—replace the ripgrep executable path, causing a command to launch when Copilot searched; the demonstrations reportedly included launching calc.exe. The author says the patch adds GetFullPath before validation, normalizing trailing dots and relative components, though the article provides limited detail about the complete fix and mitigation scope.

Takeaway

The article’s central warning is that AI-agent containment must survive a compromised or misaligned agent, including filesystem inputs that exploit platform-specific canonicalization. A seemingly harmless trailing dot was enough to turn a filename check into an arbitrary-command-execution path, reinforcing the author’s advice to patch affected installations and treat AI agents as untrusted.
