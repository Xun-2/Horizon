Copilot 路径校验绕过导致远程代码执行

Embrace The Red 介绍了一项影响 Visual Studio Copilot 和 SQL Server Management Studio（SSMS）的远程代码执行漏洞，根因位于共享组件 Microsoft.VisualStudio.Copilot.Core.dll。 Copilot 本应禁止代理修改 MCP 和 IDE 设置等敏感配置，但 Windows 对文件名的规范化方式与应用层字符串校验不一致，使这一安全边界失效。

背景

Embrace The Red 介绍了一项影响 Visual Studio Copilot 和 SQL Server Management Studio（SSMS）的远程代码执行漏洞，根因位于共享组件 Microsoft.VisualStudio.Copilot.Core.dll。Copilot 本应禁止代理修改 MCP 和 IDE 设置等敏感配置，但 Windows 对文件名的规范化方式与应用层字符串校验不一致，使这一安全边界失效。

方案

Windows 文件名末尾的 ASCII 点号在 Win32 文件操作中通常会被忽略，因此 .mcp.json. 与 .mcp.json 实际指向同一文件；校验逻辑却只比较字符串，因而错误地认为前者不是受保护文件。作者还发现，受信任 Extensions 目录开头的路径可以借助 ..\ 解析到目录外，从 SSMS.isolation.ini 获取安装标识，进而定位用户 settings.json；类似问题也存在于 settings.VisualStudio.json。攻击者可以通过间接提示注入诱导被劫持的 Copilot 写入恶意 MCP 配置、启用服务器并移除禁用项，让 IDE 启动攻击者命令；Visual Studio 还可篡改 ripgrepPath，使 Copilot 搜索时启动任意程序。微软将漏洞评为 Important，CVSS 为 8.8，并在补丁中加入 GetFullPath，以规范化尾随点和相对路径，但作者指出，修复研究也暴露出 AI 代理在自身已被误导或攻陷时仍必须维持安全控制这一更广泛的问题。

启示

文章的核心结论是，AI 代理的文件操作权限不能依赖未经规范化的路径字符串检查；一个看似无害的尾随点就可能把受限写入转化为任意命令执行。作者因此强调应从“代理可能已被攻陷”的前提出发设计防护，并及时更新 Visual Studio 与 SSMS。
